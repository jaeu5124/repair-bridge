# 리페어 브릿지 배포 안내

고장난 물건의 수리를 돕고, 수리 실패 기록을 정책 근거 데이터로 모으는 앱입니다.
이 문서대로 하면 인터넷 주소가 생기고, 휴대폰 홈 화면에 앱으로 설치됩니다.

배포에 걸리는 시간은 처음 해도 20분 정도입니다. 무료입니다.

---

## 왜 서버가 필요한가

AI에게 질문하려면 API 키가 필요합니다. 이 키는 돈이 나가는 계정 열쇠라서
브라우저 코드에 넣으면 누구나 개발자도구로 꺼내 쓸 수 있습니다.

그래서 구조를 이렇게 나눴습니다.

    [사용자 브라우저] → [우리 서버 /api/diagnose] → [Claude API]
                          여기에만 키가 있음

`api/` 폴더의 두 파일이 그 서버입니다. 별도 컴퓨터를 살 필요는 없고,
Vercel이라는 무료 서비스가 대신 실행해 줍니다.

---

## 1단계 — API 키 발급

1. https://console.anthropic.com 접속 후 가입
2. 좌측 메뉴에서 **API Keys** → **Create Key**
3. 생성된 키를 복사해 둡니다. `sk-ant-` 로 시작합니다.

키는 한 번만 보여줍니다. 못 봤으면 새로 만들면 됩니다.

> 무료 크레딧이 소진되면 결제 수단 등록이 필요합니다.
> 발표 시연 정도의 사용량은 매우 적습니다.

**주의: 이 키를 GitHub에 올리거나 카카오톡으로 공유하지 마세요.**

---

## 2단계 — GitHub에 코드 올리기

1. https://github.com 가입
2. 우측 상단 **+** → **New repository**
3. 이름은 `repair-bridge`, **Public** 선택 후 생성
4. 다음 화면에서 **uploading an existing file** 클릭
5. 이 폴더의 파일을 전부 끌어다 놓습니다

이때 `api` 폴더가 폴더째로 올라가야 합니다.
파일만 낱개로 올리면 서버가 동작하지 않습니다.

올라가야 하는 것:

    index.html
    manifest.webmanifest
    sw.js
    icon.svg
    icon-512.png
    vercel.json
    api/diagnose.js
    api/brief.js

---

## 3단계 — Vercel로 배포

1. https://vercel.com 접속 → **Continue with GitHub** 로 가입
2. **Add New** → **Project**
3. 방금 만든 `repair-bridge` 저장소 옆 **Import** 클릭
4. 설정 화면에서 **Environment Variables** 를 펼칩니다
5. 다음을 입력합니다

   - Name: `ANTHROPIC_API_KEY`
   - Value: 1단계에서 복사한 키

6. **Deploy** 클릭

1~2분 뒤 `https://repair-bridge-xxxx.vercel.app` 같은 주소가 나옵니다.
이게 완성된 앱 주소입니다.

---

## 4단계 — 휴대폰에 앱으로 설치

**안드로이드 (크롬)**
주소 접속 → 우측 상단 점 세 개 → **앱 설치** 또는 **홈 화면에 추가**

**아이폰 (사파리)**
주소 접속 → 하단 공유 버튼 → **홈 화면에 추가**

설치하면 주소창 없이 전체 화면으로 뜹니다. 일반 앱과 구분이 안 됩니다.

---

## 확인 사항

배포 후 이것부터 점검하세요.

1. 질문에 답하고 **진단 받기** → 진단서가 나오는가
2. 진단서 맨 위에 황동색 **시연 모드** 띠가 없는가

띠가 보인다면 API 연결이 안 된 상태입니다. 원인은 대개 셋 중 하나입니다.

- 환경 변수 이름 오타 (`ANTHROPIC_API_KEY` 정확히)
- 환경 변수 추가 후 재배포를 안 함
  → Vercel의 Deployments 탭에서 **Redeploy**
- API 크레딧 소진

Vercel의 **Logs** 탭에 실제 오류 메시지가 찍힙니다.

---

## 발표 당일 대비

행사장 와이파이가 불안정할 수 있습니다.
API가 안 되면 앱이 자동으로 시연 모드로 넘어가 내장 규칙으로 진단서를 만듭니다.
발표가 끊기지 않습니다. 다만 진단서에 시연 모드라고 표시됩니다.

설치형 앱은 한 번 열어두면 오프라인에서도 화면이 뜹니다.
발표 전에 미리 한 번 접속해 두세요.

---

## 파일 설명

| 파일 | 역할 |
|---|---|
| `index.html` | 앱 화면 전체. 질문, 진단서, 도해, 이력, 정책 데이터 |
| `api/diagnose.js` | 진단 요청을 받아 Claude에게 전달 |
| `api/brief.js` | 수리 실패 기록으로 정책 브리프 작성 |
| `sw.js` | 오프라인 실행 담당 |
| `manifest.webmanifest` | 앱 이름과 아이콘 정보 |
| `vercel.json` | 배포 설정 |

---

## 데이터가 어디에 저장되는가

수리 이력은 사용자 휴대폰 안에만 저장됩니다. 서버로 전송되지 않습니다.
따라서 현재 버전의 정책 데이터는 개인 단위 집계입니다.

여러 사용자의 기록을 모으려면 데이터베이스가 필요합니다.
발표에서는 이 점을 한계이자 다음 단계로 밝히는 편이 좋습니다.
심사위원이 물어볼 가능성이 높은 지점이기도 합니다.
